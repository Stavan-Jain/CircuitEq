# T-count survey: does PyZX's output align with its input by windows?

The roadmap's working hypothesis (Rung 3) is that an optimiser's output
relates to its input by local rewrites that can be aligned as windows, so
that `circuit_windows` proves the pair from an alignment an agent (here, a
script) writes down. This directory is the evidence run: eleven T-heavy
circuits, two PyZX pipelines each, an alignment script, and a Lean check
of every alignment it found. The account of the pairs where no alignment
was found, and why, is the second half of this file.

**Headline.** Phase teleportation (`teleport_reduce` + `basic_optimization`)
is skeleton-preserving and its output aligns for 8 of the 11 circuits; two of
those alignments (`tof_3`, `barenco_tof_3`) have windows of at most three
wires and are kernel-checked, four (`tof_4`, the three Cuccaro adders) need
one kind of window on five wires, which the current evaluator cannot decide
inside ten minutes (`tof_4`'s was run and killed after eight minutes), and
two (`mod5_4`, the 4-qubit random circuit) only align as windows spanning
the whole register, which is a brute-force basis decide and not a window
proof. Full re-synthesis (`full_reduce` + extraction) aligns only as a
single whole-register window, for three of the smallest circuits, and not
at all for the other eight; three of the random pairs are equivalent only
up to a global phase, which `circuit_windows` cannot state. The failures
sort into five mechanisms, listed below; none of them is "the rewrite was
not local", two are library gaps, one is the decide cost, one is
`full_reduce` being a re-synthesis, and one is a global scalar. A
phase-polynomial checker has since landed on `main`
(`CircuitEq/PhasePoly.lean`, not available in this survey's worktree and
not used); the section "Where the phase-polynomial checker applies" shows
that it would decide every wide window of the structured teleport pairs,
at any width, after a cut at the Hadamards.

## Pipelines

The two pipelines of `scripts/check_pyzx_benchmarks.py`, PyZX **0.9.0**:
`teleport` is `teleport_reduce`, `Circuit.from_graph(...).to_basic_gates()`,
`basic_optimization`; `full_reduce` is `full_reduce`, `extract_circuit`,
`to_basic_gates`, `basic_optimization`. Outputs are saved as
`<name>/pyzx_teleport.qasm` and `<name>/pyzx_full_reduce.qasm` and
translated to the Lean alphabet exactly as the check script does (`cz` to
`H; CX; H`, `rz(k·π/4)` to the diagonal Clifford+T gate with that matrix).

## Method: `scripts/tcount_survey.py`

For each pair the script

1. **canonicalises** both instruction lists: a priority topological sort
   (`greedy`) or a longest-path layering (`asap`) of the dependency DAG
   under a commutation relation, either the tactic's own `Instr.CanCommute`
   (`cancommute`) or disjoint wires only (`strict`); `raw` keeps the QASM
   order. Two lists that differ only by licensed reorderings then coincide;
2. **diffs** the canonical lists with `difflib.SequenceMatcher` and turns
   each opcode into a window: `replace` is `(a, b)`, `delete` is `(a, [])`,
   `insert` is `([], b)`, `equal` runs are matched context;
3. **replays** the alignment in a Python model of `circuit_windows`: the
   same `CanCommute` rules, the same "first occurrence that commutes with
   everything before it" pull, windows fired as early as both sides can be
   pulled to the front. The model tries every pending window at each step,
   which yields the order the tactic must be given them (it only ever tries
   the next one). Each window is also checked numerically as a unitary on
   its own wires, an untrusted oracle used for diagnosis only;
4. **refines** on failure, a bounded number of times (40 steps, windows
   capped at 8 wires): a window that is not an equivalence on its own is
   merged with the smallest subset of the other such windows that makes
   one (up to four, at most 400 trials), or grown by the nearest context
   gate that does not commute with it; a window the model cannot fire
   around absorbs the context gates it must fire around (the replay's own
   firing conditions, derived from the tactic); a blocked move absorbs its
   blocking gate into the window that owns it, or opens a new commutation
   window. Identical gates of a pure deletion and a pure insertion may
   first be re-paired as context (a single move perturbs the canonical
   order of nearby independent gates and the diff reports them deleted
   and re-inserted); this is tried both ways;
5. runs all ten searches (five canonical orders, re-matching on and off)
   and keeps the replayable alignment with the narrowest widest window and
   then the smallest estimated decide cost (gates times `4^k`);
6. **emits a Lean file** with `original`, `optimized` and
   `theorem original_equiv_optimized : original ≡ᵤ optimized := by
   circuit_windows [...]` and checks it with `lake env lean` under a
   timeout of 600 s, if the widest window has at most 4 wires (the bound
   comes from the cost measurements below; alignments above it are
   reported as found but unchecked, and one 5-wire alignment was run to
   record an actual timeout).

Lean is the judge. The model's job is to write the alignment down and to
order it; the tactic accepted every alignment the model accepted (no model
mismatch was observed), and every "no alignment" verdict below is the
model's, with its reason, since there is nothing to send to Lean then.
Results are in `results.json` (one record per pair with every attempt's
report, the windows, the refinement log and the Lean output);
`--table` prints the table below.

## Rerun on `main` with the dyadic evaluator

The survey above was run on the branch's base, whose basis evaluator worked
in `ℚ(ζ₈)` with rational normalisation. After the merge, `main` decides
windows with the gcd-free `Dyadic8` closure evaluator (`CircuitEq/Dyadic.lean`),
and the width-blocked pairs were rerun on it with `--lean-max-wires 5` and a
300 s cap; the table has been updated with these rows.

|---|---|---|
| `tof_4` / teleport (6 windows, widest 5 wires, 42 gates) | killed at 8 min, 2.1 GB | **yes**, 5.9 s |
| `cuccaro_2` / teleport (4 windows, widest 5w / 31g) | not sent (5 wires) | **yes**, 5.0 s |

So the width limit that section 5 below describes has moved from four wires
to about five, and time is no longer the constraint at these sizes: memory
is. `cuccaro_4` is the first pair to fail on memory alone, and the culprit
is not the window (the same 5-wire windows pass on `cuccaro_3`) but the
replay of a 155-gate certificate, whose intermediate terms the kernel's
`whnf` cache retains for the whole declaration. A compact encoding of the
instruction list and chunked replay are the levers (`QUEUE.md`). The
`full_reduce` rows and the global-phase rows are unchanged by the
evaluator: their failures are structural, not a matter of cost.

## Reading the results

**Aligned with narrow windows, kernel-checked.** `tof_3` (4 windows: the
`T·T = S` merge on wire 0, the two inserted `H; H` pairs of the `CZ; H`
rewrites, and the `CZ` that moved through a CNOT on its control, 3 wires
and 10 gates, which is the hand-written module's fourth window verbatim;
6.6 s) and `barenco_tof_3` (6 windows, every one on a single wire: two
`T·T = S` merges, three inserted `H; H` pairs from `CZ; H` rewrites, one
cancelled `H; H` pair; 2.3 s). `barenco_tof_3`'s alignment is the raw diff
with no refinement step; `tof_3`'s needed one re-match and one context
absorption, which is how the script arrives at the hand alignment's `CZ`
window. `barenco_tof_3` is promoted to
`CircuitEq/Benchmarks/BarencoTof3.lean`; `Tof3.lean` keeps its
hand-written four windows, which differ from the script's only in grouping
the inserted `H; H` pairs with their `H; CX`.

**Kernel-checked, but as a whole-register decide.** The 4-qubit random
circuit's teleport pair: 3 windows, two of which span all four wires (9
and 24 gates), 64 s. This is a proof, but not a window proof: on 4 qubits
the register is the window, and the decide is the brute-force basis check
that the window pattern exists to avoid. It is not promoted.

**Aligned, but a window is too wide to decide.** `tof_4`: five one-wire
windows and one window on 5 wires and 42 gates, the `CZ` from the last
Toffoli's `H; CX` commuted backwards through the whole fourth Toffoli and
the interleaved tails of the second and third (see mechanism 3); the
alignment was run once at the 5-wire bound and the Lean check was killed
after about eight minutes at 2.1 GB resident (mechanism 5). The three
Cuccaro adders: 4, 6 and 8 windows, widest 5 wires and 31–33 gates, and the
alignment is *periodic*: the first two windows of `cuccaro_2` recur
verbatim in `cuccaro_3` and `cuccaro_4`, and each further bit adds one
window of the same shape on the next wires plus one `CZ`-through-a-control
window of 3 wires and 8 gates (mechanism 4). The number of windows grows
linearly with the number of bits and the widest window does not grow: the
hypothesis holds for the adder family, and the obstacle is purely the
`2^k` cost of a 5-wire decide (mechanism 5).

**Aligned only as the whole register.** `mod5_4` (both pipelines, 5 wires
and 108 or 90 gates, not sent to Lean; the teleported output re-attributes
phases along parity terms of the whole circuit, mechanism 4), the 4-qubit
random circuit under `full_reduce` (59 gates; sent to Lean and killed by
the 600 s cap at 3.4 GB resident) and under `teleport` (above), and
`cuccaro_2` under `full_reduce` (6 wires, 147 gates, not sent). These five
are listed in the table as "(whole register)": the search found no
structure, only the fact that the pair is small enough to decide outright.

**No alignment.** The other eight `full_reduce` pairs (mechanism 1), the
three global-phase pairs (mechanism 2), `tof_5`'s teleport output
(mechanism 3 with two nested `CZ` moves; the window passes 8 wires) and
the 6-qubit random circuit's teleport output (mechanism 4).

## The failure modes

### 1. Re-synthesis: `full_reduce` discards the skeleton

The diff matches 3–21 of 30–137 gates for the `full_reduce` pairs
(`mod5_4` 3/63, `cuccaro_4` 5/137, `tof_4` 14/75) against 42–113 for the
teleport pairs of the structured circuits (`tof_3` 42/45, `tof_4` 68/75,
`cuccaro_4` 113/137). What is left is not a set of windows but two
different circuits for the same unitary: the extracted circuit has
different CNOT structure, its phases sit on different parity terms, and
the search's windows are not equivalences on their own and cannot be
merged into equivalences within 8 wires. This is the expected outcome and
the roadmap already says so ("re-synthesised output has no alignment; that
is the residual pattern's job"); the survey confirms it on eleven circuits
and adds a number: no `full_reduce` pair had a window smaller than the
register that was an equivalence on its own. Three pairs (`random_4q`,
`mod5_4`, `cuccaro_2`, on 4, 5 and 6 qubits) aligned as the whole
register, and for the other eight the search found nothing within its
bounds. The only `full_reduce` pair the search could hand to the tactic,
the 4-qubit whole-register decide, timed out at 600 s (mechanism 5); no
`full_reduce` pair is kernel-checked, and none is promoted.

### 2. A global phase

`random_5q_d45_s2` (both pipelines) and `random_6q_d60_s3`
(`full_reduce`) are equivalent only up to a global phase (`e^{-iπ/4}`,
`e^{-iπ/2}`, `e^{3iπ/4}` respectively, measured numerically). PyZX's ZX
rewriting tracks scalars in the graph and extraction drops them; the
`rz` semantics used here (`diag(1, e^{ikπ/4})`, no global phase) is PyZX's
own, so this is not a translation artifact. `circuit_windows` is stated on
`≡ᵤ`, and a phase cannot be absorbed into any window because every window
is an exact equivalence on its wires. The library has `≡ₚ`
(`EquivalentUpToPhase`, decidable) but no window pattern for it; the fix is
one extra step kind in the certificate language (a scalar window), not a
new technique. Until then these pairs are out of reach and are reported as
such rather than as alignment failures.

*Since this run:* the window pattern has learned `≡ₚ`. `circuit_windows`
accepts a goal `a ≡ₚ b` or `a ≡ₚ[k] b`, each window may hold up to a phase
of its own, and the certificate is replayed by `replayPhase`, which adds
the windows' phases up (`CircuitEq/Certificate.lean`). It took no new step
kind, only a second interpretation of `window`. The survey has not been
rerun: its three phase-only pairs are random circuits with no alignment,
so for them the statement is now available but the proof is still the
whole-register decide of `≡ₚ` (`scripts/chunked_decide.py --phase`).

### 3. A diagonal two-qubit gate commuted through a control-only block

`basic_optimization` rewrites `H t; CX c t` as `CZ c t; H t` and then
commutes the `CZ` freely through every gate that uses `c` and `t` as CNOT
controls or diagonal gates. In `tof_3` it moved one `CZ` through a single
`CX` on its control, and the hand alignment paid for that with one 3-wire
window. In `tof_4` the `CZ 1 4` of the last Toffoli moved through the
entire fourth Toffoli (`CCX 4 2 5`: wire 4 is only ever a control there)
and the interleaved tails of the second and third, so the smallest window
that contains the move touches wires 4, 2, 5, 1 and 3 and holds 42 gates.
In `tof_5` two such moves nest and the search gives up at 8 wires. The
Cuccaro adders show the same move in its small form, `[CX 2 3, H 2, CX 1 2]
↔ [H 2, CX 1 2, H 2, CX 2 3, H 2]`, once per bit.

This is a library gap, not a locality failure: the move is licensed gate
by gate for a genuine `CZ`, but in this alphabet a `CZ` is `H; CX; H` and
`Instr.CanCommute` is a relation on single instructions, so the tactic
cannot move the triple as a unit. Two repairs are possible without any
new evaluator: a `CanCommute`-style rule for the pattern `[H t, CX c t,
H t]` against a gate that uses `t` and `c` only as controls or diagonally
(a `sound` lemma from `cnot_diag_control_comm`, since `CZ` is diagonal),
or a `calc` chain of several `circuit_windows` calls with intermediate
circuits, one 3-wire window per CNOT the `CZ` passes. The certificate
language should have the block move as a step kind. Not patched here,
per the task's instructions.

### 4. Phase re-attribution along parity terms

Phase teleportation works on the phase polynomial: a phase on a wire that
carries the parity `x_i ⊕ x_j` after a CNOT is the same term as a phase on
any other wire that carries that parity anywhere else, and PyZX realises
each term's total phase at one place of its choosing. When the two places
are connected by CNOT *controls* only, the move is a sequence of licensed
commutations and the window is the merge itself (`[T 0, T 0] ↔ [S 0]`);
this is every window in `tof_3` and `barenco_tof_3`. When they are
connected through CNOT *targets*, no chain of single-gate commutations
exists, and the window must contain the CNOTs whose targets carry the
term. For the adders that region is the MAJ block of one bit, 5 wires and
about 31 gates, and it repeats per bit (the diff shows it directly:
`cuccaro_2`'s output starts `Sdg 1; CX 2 0; CX 2 1; S 2; H 2`, a phase on
the target of the very next CNOT). For `mod5_4`, whose four CCZs all
target wire 4, the parity terms span the whole circuit (`T 0, T 0` at
opposite ends become one `Z 0`, a `Z 3` appears from nowhere), and the
only window is the register. The 6-qubit random circuit's teleport output
is the same phenomenon with no structure to exploit: its `[] ↔ [S 0]`
insertions have no non-commuting context to grow into because the source
phases are on other wires. The random circuits are also where the
teleport pipeline matches least (17 of 30, 18 of 45 and 17 of 60 gates):
with no structure to respect, `basic_optimization` cancels adjacent CNOT
pairs, conjugates CNOTs by Hadamards and reorders freely, so even the
skeleton-preserving pipeline leaves little skeleton.

This is what the roadmap calls the residual pattern: cut points with a
diagonal residual. The right certificate step is a phase-polynomial
window, "these two CNOT+phase regions have the same linear map and the
same phase polynomial", checked by a certified normal form rather than a
basis decide; it would make every structured teleport pair in this survey
a proof with windows no wider than the wire count of one region. That
checker has since landed on `main` as `CircuitEq/PhasePoly.lean`; the
section "Where the phase-polynomial checker applies" says which windows it
would take.

### 5. The decide cost of a 5-wire window

*Partly superseded by the rerun above: on `main` the 5-wire windows of
`tof_4` and the adders decide in seconds; memory, not time, is now the limit.*

Measured with `lake env lean` on the same machine during the same hours
(a 10-core laptop with 16 GB, shared with four other agents' Lean builds
and paging for most of the run, so every number carries a large load
component): `barenco_tof_3`, six one-wire windows, 2.3 s in the survey and
2.0 s standalone; `tof_3`, one 3-wire 10-gate window, 6.6 s; the 4-qubit
random teleport pair, two whole-register windows of 9 and 24 gates, 64 s;
the 4-qubit random `full_reduce` pair, one whole-register window of 59
gates, killed by the 600 s cap at 3.4 GB resident; `tof_4`'s 5-wire
42-gate window, killed by hand after about 8 minutes at 2.1 GB resident
with the machine at 95 % swap. A synthetic probe (`T 0` commuting through
a CNOT chain and back) gave 18 s for 3 wires and 12 gates, 42 s for 4 wires
and 16 gates (both including an import that took 27 s while paging) and no
answer in 900 s for 5 wires and 20 gates. The growth from 4 to 5 wires and
from 24 to 59 gates is far more than the `O(d · 4^k)` list steps predict,
and the resident sizes say why: the kernel's evaluation caches for one
long decide grow into gigabytes and the machine pages. Two consequences:
several short windows are much cheaper than one long window of the same
total size (33 gates in two 4-wire windows took 64 s, one 4-wire window
of 59 gates did not finish), and every 5-wire window in this survey
(31–42 gates) is outside a ten-minute budget on this evaluator. They are
reported as "found, unchecked" (and `tof_4` as the one recorded timeout).
This is Rung 1's gcd-free coefficient representation, or, better, the
checkers of mechanisms 3 and 4, which make those windows unnecessary.

### 6. Search artifacts (not failures of the hypothesis)

- **Spurious reorderings** from `Circuit.from_graph` and
  `basic_optimization` disappear under the canonical orders: the raw diff
  of `tof_3` has 11 windows, the canonical one 5 (4 after refinement);
  `tof_4` 19 versus 9; `tof_5` 25 versus 13; `barenco_tof_3` 9 versus 6.
  Every alignment in the table came from one of the two orders under the
  tactic's own relation; the strict (disjoint-wire) orders never did
  better and found nothing for the adders, and the raw order found only
  whole-register windows.
- **A single move perturbs the canonical order** of nearby independent
  gates, and the diff then reports them deleted here and inserted there.
  Re-pairing such gates as context helped `tof_4` (whose `CZ` move
  displaced `Tdg 5; CX 4 5`) and hurt `barenco_tof_3` (it paired a
  cancelled `H; H` with an inserted one as a move, which then had to
  absorb its blockers into a 3-wire window instead of two 1-wire ones);
  the script tries both.
- **The tactic pulls the first occurrence that commutes**, so equal gates
  on one wire are interchangeable for it; the model reproduces this and
  no pair failed because of it.

## Where the phase-polynomial checker applies

`CircuitEq/PhasePoly.lean` landed on `main` while this survey ran in a
worktree cut before it, and was not used here. It decides pairs of
CNOT+diagonal circuits of any width by a certified normal form, at a cost
that does not grow as `2^k`. To see where it would apply, every wide window
in the table was analysed (with a numpy script outside the deliverable, an
untrusted oracle) as follows: put both sides in CZ form by cancelling
`H; H` pairs and moving every Hadamard that is not at the window boundary
as far as it goes (`H t; CX c t = CZ c t; H t` and `CX c t; H t = H t;
CZ c t` through a CNOT target, `X; H = H; Z`, freely past other wires,
stopped by any other gate on its wire), trying every combination of
directions; the Hadamards that stay inside cut each side into segments,
each gate going to the earliest segment its non-commuting predecessors
allow (the tactic's own relation, with `CZ` as a two-wire diagonal gate);
accept the cut if the Hadamard layers agree on both sides, every segment
is CNOT+diagonal, and every pair of segments is equivalent on its own.

- **Every wide window of the structured teleport pairs passes.** The
  adders' 5-wire windows (31–33 gates) are two CNOT+diagonal pairs (10 v 12
  and 2 v 1 gates, or 11 v 13 and 2 v 1) around one interior Hadamard, a
  Toffoli's target `H`, with the other Hadamard a common boundary;
  `tof_4`'s 5-wire 42-gate window is two pairs (7 v 7 and 10 v 10) around
  `H 5`; the 3-wire `CZ`-through-a-control windows (`tof_3`'s and one per
  adder bit) and the adders' first 3-wire window are single pairs (3 v 3,
  2 v 2, 5 v 6) with a boundary Hadamard. `mod5_4`'s teleport pair is a
  single CNOT+diagonal pair of 50 v 48 gates on all five wires with `H 4`
  as the boundary: the whole-register decide that cannot finish becomes
  one phase-polynomial check.
- **Both library gaps are inside the fragment.** The mechanism-3 move (a
  `CZ` through CNOT controls) and the mechanism-4 re-attributions are
  CNOT+diagonal identities once `H; CX; H` is read as `CZ`, for instance
  the adders' recurring `[CX 4 3, CZ 3 4] ≡ᵤ [Sdg 3, CX 4 3, S 4, S 3]`.
  So for the structured circuits the checker subsumes both: with
  `circuit_windows` taking PhasePoly as the leaf oracle in place of
  `decide +kernel`, and with windows chosen as the segment pairs between
  common Hadamard layers (a choice, not a new step kind; the segment
  reordering is the tactic's own pull), `tof_3`, `tof_4`, the adders and
  `mod5_4`'s teleport pair are proofs with no basis decide wider than one
  wire, and the adder proofs are one template per bit. `tof_5` was not
  analysed because its alignment grew past 8 wires while chasing two
  nested `CZ` moves; with the move certified it would look like `tof_4`'s.
- **What it does not reach.** The random circuits (the two sides' Hadamard
  skeletons differ, so no common cut exists; `random_4q`'s 24-gate window
  is the example), every `full_reduce` pair (different Hadamard skeleton,
  and `mod5_4`'s has an `X` inside a segment) and the global-phase pairs.
  Those need the general machinery, Hadamard gadgets or path sums, and
  `≡ₚ` respectively.

## Consequences for the roadmap

The hypothesis survives for phase teleportation: on every circuit with
structure, the output is the input plus local rewrites, and the alignment
is mechanical (a diff under the tactic's commutation relation plus a replay
of the tactic's rules). What fails is the *checker*: the basis decide
cannot afford the 5-wire windows the moves need, and the two library gaps
(a block move for diagonal gates, a phase re-attribution across CNOT
targets) are both CNOT+diagonal identities. The phase-polynomial checker
closes both for the structured circuits, as the previous section shows,
and makes the adder proofs periodic. Re-synthesis remains out of reach of
any window pattern, as predicted, and the random circuits show that
`basic_optimization` alone can destroy the skeleton when there is none to
respect.

## Reproduce

```bash
/tmp/circuiteq-pyzx-venv/bin/python scripts/tcount_survey.py --self-test
/tmp/circuiteq-pyzx-venv/bin/python scripts/tcount_survey.py --generate
/tmp/circuiteq-pyzx-venv/bin/python scripts/tcount_survey.py --timeout 600 --lean-max-wires 4
/tmp/circuiteq-pyzx-venv/bin/python scripts/tcount_survey.py --table
```

`--no-lean` runs the model only (seconds); `--circuits`/`--pipelines`
select pairs; `--emit NAME PIPELINE` prints the Lean module of one aligned
pair, which is how the promoted benchmark was produced. The script checks
the PyZX version, regenerates each `pyzx_*.qasm` and warns if it differs
from the saved one, and writes every Lean file it checks to `--workdir`.
The recorded `tof_4` timeout came from a second pass,
`--lean-max-wires 5 --circuits tof_4 --pipelines teleport`; a 5-wire
decide needs gigabytes of memory on this evaluator, so do not run it on a
loaded machine.
